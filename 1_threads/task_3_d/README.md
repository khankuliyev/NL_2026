# 1.3 Параллельная проверка гипотезы Коллатца

Тема: Многопоточность  
Язык: D  
Ветка: `1_task_3_d`

## Постановка задачи

Для натурального n последовательность Коллатца строится так: чётное число делится на 2, нечётное заменяется на 3n+1, пока не получится 1. Для всех чисел от 1 до N требуется найти число с самой длинной последовательностью и число, у которого промежуточное значение получается наибольшим. Диапазон делится на блоки, блоки обрабатываются параллельно через `parallel` из `std.parallelism`, частичные результаты объединяются через `taskPool.reduce`. Переполнение промежуточных значений проверяется.

Входные данные: граница диапазона N задаётся аргументом командной строки, число потоков перебирается программой (1, 2, 4, ...).

Выходные данные: число с самой длинной последовательностью и её длина, число с наибольшим промежуточным значением, время работы и ускорение для каждого числа потоков.

## Реализация

- `collatz` строит последовательность в `ulong`. Перед шагом 3n+1 проверяется, что `n <= (ulong.max - 1) / 3`. Если нет, фиксируется переполнение, и число пропускается с предупреждением.
- Диапазон 1..N делится на блоки по 10 000 чисел. Блоки обрабатываются через `pool.parallel(partial, 1)`, каждый блок даёт свой `Result` (самая длинная последовательность и наибольшее промежуточное значение).
- Частичные результаты объединяются через `pool.reduce!combine`. При равенстве берётся меньшее число, поэтому итог не зависит от порядка объединения. Программа проверяет, что на любом числе потоков результат совпадает с однопоточным.
- Для каждого числа потоков t (1, 2, 4, ..., число ядер) создаётся `TaskPool(t - 1)`: вызывающий поток тоже участвует в работе.

## Сборка и запуск

Нужен компилятор D (LDC или DMD) и `dub`.

```bash
dub build -b release --compiler=ldc2
./collatz 1000000
```

Без dub: `ldc2 -O3 -release source/app.d -of=collatz`.
