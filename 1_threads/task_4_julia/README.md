# 1.4 Параллельное моделирование теплопроводности на пластине

Тема: Многопоточность  
Язык: Julia  
Ветка: `1_task_4_julia`

## Постановка задачи

Дана прямоугольная пластина, разбитая на сетку N×M. На краях пластины поддерживается постоянная температура (например, один край горячий, остальные холодные). Требуется найти установившееся распределение температуры внутри методом Якоби: новое значение в каждой точке равно среднему четырёх соседей на прошлой итерации. Строки сетки на каждой итерации обновляются параллельно через `Threads.@threads`, используются два массива, чтобы потоки не мешали друг другу. Итерации останавливаются, когда максимальное изменение становится меньше заданной точности.

Входные данные: размер сетки, температуры на краях и точность задаются аргументами командной строки, число потоков задаётся при запуске Julia (`-t`).

Выходные данные: число итераций, время работы, итоговое поле температуры в виде изображения в файле PGM (светлее значит горячее).

## Реализация

- Сетка хранится как `T[x, y]`, где `y` это строка пластины. Julia хранит массивы по столбцам, поэтому строка пластины лежит в памяти подряд, и внутренний цикл идёт по ней.
- Внутренние строки делятся на k блоков. На каждой итерации блоки обновляются параллельно через `Threads.@threads :static`. Чтение идёт из массива `src`, запись в `dst`, затем массивы меняются местами, поэтому потоки не мешают друг другу. Каждый блок возвращает своё максимальное изменение, общий максимум сравнивается с точностью.
- Программа прогоняет расчёт для k = 1, 2, 4, ..., `Threads.nthreads()` и проверяет, что поле на любом числе потоков совпадает с однопоточным. При k = 1 строки считаются без `@threads`, чтобы в однопоточное время не попадал запуск задач.
- Углы пластины получают среднее двух соседних краёв. Итоговое поле сохраняется в двоичный PGM (P5): температура линейно переводится в яркость 0..255, светлее значит горячее.

## Запуск

Нужна Julia 1.9 или новее, внешних пакетов нет.

```bash
julia -t 16 heat.jl 300 300 100 0 50 0 1e-6 plate.pgm
```

Аргументы: число строк N, число столбцов M, температуры верхнего, нижнего, левого и правого края, точность, имя PGM-файла (по умолчанию `plate.pgm`). Число потоков задаётся ключом `-t`.

```

       2      147074        26.629        1.10
       4      147074        15.993        1.84
       8      147074        10.379        2.83
      16      147074         8.677        3.39
```

Проверка: для квадратной пластины температура в центре равна среднему четырёх краёв, здесь (100 + 0 + 50 + 0) / 4 = 37.5. Расчёт `julia -t 8 heat.jl 101 101 100 0 50 0 1e-6` даёт в центре 37.498.

## Замечания

- Метод Якоби за одну итерацию меняет поле очень мало, поэтому на большой сетке условие «изменение меньше точности» срабатывает раньше, чем поле действительно установится. Чем больше сетка, тем меньше нужна точность (порядка 1e-6 для 300×300).
- Ускорение ограничено. Одна итерация на сетке 300×300 занимает около 0.2 мс, и заметную часть этого времени съедает запуск задач `@threads` на каждой итерации. Кроме того, на гибридном процессоре (i9-12900H, P- и E-ядра) часть потоков работает на медленных ядрах. Переход от 2 к 4 потокам даёт скачок, потому что блок каждого потока начинает помещаться в кеш L2 ядра.
