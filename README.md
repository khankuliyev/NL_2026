# NL_2026

Индивидуальная работа по курсу «Новые языки программирования»: 20 программ на 20 разных языках программирования.
Пять тем, на каждую тему по 4 программы.

Студент: Кулиев Хакберди, группа 5030102/30401.

## Порядок работы

Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`,
например `1_task_1_rust`.
Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.
В папке каждой задачи есть свой README с постановкой и командами запуска.

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Параллельный поиск файлов-дубликатов | Rust | `1_task_1_rust` |
| 2 | Симуляция касс супермаркета на агентах | Clojure | `1_task_2_clojure` |
| 3 | Параллельная проверка гипотезы Коллатца | D | `1_task_3_d` |
| 4 | Параллельное моделирование теплопроводности на пластине | Julia | `1_task_4_julia` |

1.1 Параллельный поиск файлов-дубликатов (Rust). Программа обходит дерево каталогов и группирует файлы по размеру. Файлы одинакового размера раздаются рабочим потокам `std::thread` через канал `mpsc`, каждый поток считает хеш содержимого. По совпадению хеша и побайтовому сравнению находятся дубликаты. Сравнивается время на 1 и на N потоках.

1.2 Симуляция касс супермаркета на агентах (Clojure). Каждая касса это агент `agent` со своей очередью покупателей, генератор покупателей работает в отдельном потоке и ставит покупателя в самую короткую очередь. Общая статистика хранится в `atom`. По окончании симуляции печатается среднее и максимальное время ожидания и загрузка каждой кассы.

1.3 Параллельная проверка гипотезы Коллатца (D). Для каждого числа из диапазона строится последовательность Коллатца до единицы. Диапазон делится между потоками через `std.parallelism`, каждый поток ищет число с самой длинной последовательностью и самое большое промежуточное значение, затем результаты объединяются. Печатается результат и время для разного числа потоков.

1.4 Параллельное моделирование теплопроводности на пластине (Julia). Пластина задаётся сеткой, на краях держится заданная температура. Температура внутри считается итерациями метода Якоби, строки сетки на каждой итерации обновляются параллельно через `Threads.@threads`. Итерации идут до установления, итоговое поле сохраняется в PGM-файл, печатается время для разного числа потоков.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Генерация и прохождение лабиринта (рекурсия) | Haskell | `2_task_1_haskell` |
| 2 | Калькулятор выражений методом рекурсивного спуска (рекурсия) | OCaml | `2_task_2_ocaml` |
| 3 | Игра «Числа»: получение целевого числа из набора (рекурсия) | Common Lisp | `2_task_3_lisp` |
| 4 | Кодирование Хаффмана | Kotlin | `2_task_4_kotlin` |

2.1 Генерация и прохождение лабиринта (рекурсия) (Haskell). Лабиринт генерируется рекурсивным поиском в глубину: из текущей клетки выбирается случайный непосещённый сосед, стена между ними убирается, и функция вызывается для соседа. Затем другая рекурсивная функция ищет путь от входа к выходу с возвратом из тупиков. Лабиринт и найденный путь печатаются в консоль символами.

2.2 Калькулятор выражений методом рекурсивного спуска (OCaml). Выражение разбивается на лексемы, затем рекурсивные функции для выражения, слагаемого и множителя строят дерево с учётом приоритетов и скобок. Дерево вычисляется, ошибки в записи выражения сообщаются с указанием позиции.

2.3 Игра «Числа»: получение целевого числа из набора (рекурсия) (Common Lisp). Даны несколько чисел и целевое число. Рекурсивная функция выбирает два числа из набора, заменяет их результатом одной из операций +, -, *, / и вызывается для уменьшенного набора. Так ищется выражение, равное целевому числу, а если точного нет, то самое близкое к нему. Печатается найденное выражение и число просмотренных вариантов.

2.4 Кодирование Хаффмана (Kotlin). Считаются частоты символов текста, по ним строится дерево Хаффмана и таблица кодов. Текст сжимается в последовательность битов и восстанавливается обратно, печатается таблица кодов и степень сжатия.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Пакетное переименование файлов по шаблону с отменой | Perl | `3_task_1_perl` |
| 2 | Форматирование текста по ширине | Ruby | `3_task_2_ruby` |
| 3 | Консольная викторина с историей результатов | Lua | `3_task_3_lua` |
| 4 | Шифрование файлов шифром Виженера | Nim | `3_task_4_nim` |

3.1 Пакетное переименование файлов по шаблону с отменой (Perl). Пользователь задаёт каталог, регулярное выражение и шаблон нового имени со счётчиком и датой. Программа показывает в консоли, как изменятся имена, проверяет конфликты и после подтверждения переименовывает файлы. Все переименования пишутся в журнал, по которому их можно отменить.

3.2 Форматирование текста по ширине (Ruby). Программа читает текстовый файл и разбивает его на абзацы. Каждый абзац переносится по словам в строки заданной ширины, строки выравниваются по левому краю, по правому, по центру или по ширине с равномерным распределением пробелов. Результат печатается в консоль и сохраняется в файл.

3.3 Консольная викторина с историей результатов (Lua). Вопросы и варианты ответов читаются из текстового файла, ответы пользователь вводит с клавиатуры. Неверный ввод переспрашивается. Результат, дата и затраченное время дописываются в файл истории, лучшие результаты можно посмотреть из меню.

3.4 Шифрование файлов шифром Виженера (Nim). Через консольное меню файл шифруется или расшифровывается побайтово по ключу, введённому пользователем. Есть режим проверки, который сравнивает расшифрованный файл с исходным.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Распределённый подсчёт слов: сервер и клиенты-работники | Elixir | `4_task_1_elixir` |
| 2 | Сервер очереди заданий с повтором при сбое исполнителя | Erlang | `4_task_2_erlang` |
| 3 | Сетевой аукцион с таймером лотов | Scala | `4_task_3_scala` |
| 4 | UDP-сервер времени и измерение задержки | Zig | `4_task_4_zig` |

4.1 Распределённый подсчёт слов: сервер и клиенты-работники (Elixir). Сервер делит большой текст на части и раздаёт их подключённым по TCP клиентам-работникам. Каждый работник считает частоты слов в своей части и отправляет результат обратно, сервер сливает словари. Если работник отключился, его часть отдаётся другому. Состояние распределения хранит GenServer.

4.2 Сервер очереди заданий с повтором при сбое исполнителя (Erlang). Клиенты-постановщики отправляют на сервер задания (например, разложить число на множители), клиенты-исполнители берут их по одному и возвращают результат. Сервер на `gen_tcp` следит за подключениями, задание отключившегося исполнителя возвращается в очередь. Постановщик может запросить статус и результат своего задания.

4.3 Сетевой аукцион с таймером лотов (Scala). Сервер по очереди выставляет лоты, у каждого есть стартовая цена и таймер. Клиенты делают ставки, сервер проверяет, что ставка выше текущей, и рассылает новую цену всем участникам. Каждая принятая ставка продлевает таймер. По окончании времени лот продаётся, итоги торгов сохраняются в файл.

4.4 UDP-сервер времени и измерение задержки (Zig). Сервер отвечает на UDP-запросы текущим временем. Клиент отправляет серию запросов, как `ping`, измеряет время ответа, считает потерянные пакеты и печатает минимальную, среднюю и максимальную задержку.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | BMP-изображение в ASCII-арт | F# | `5_task_1_fsharp` |
| 2 | Субтитры SRT в WebVTT со сдвигом времени | Swift | `5_task_2_swift` |
| 3 | Контакты vCard в CSV | Groovy | `5_task_3_groovy` |
| 4 | S-выражения в JSON и обратно | Scheme | `5_task_4_scheme` |

5.1 BMP-изображение в ASCII-арт (F#). Программа сама разбирает заголовок 24-битного BMP-файла и читает пиксели с учётом выравнивания строк. Изображение уменьшается до заданной ширины, яркость каждого блока пикселей переводится в символ из шкалы плотности. Результат записывается в текстовый файл, есть режим инверсии для тёмного фона.

5.2 Субтитры SRT в WebVTT со сдвигом времени (Swift). Программа разбирает файл субтитров SRT: номера реплик, интервалы времени и многострочный текст. Можно сдвинуть все реплики на заданное время или растянуть их под другую частоту кадров. На выходе файл WebVTT, проверяются пересечения реплик и ошибки во времени.

5.3 Контакты vCard в CSV (Groovy). Программа разбирает файл vCard (.vcf) с несколькими контактами: склеивает перенесённые строки, понимает параметры полей и несколько телефонов и адресов с типами. Набор столбцов собирается по всем контактам, результат записывается в CSV с правильным экранированием.

5.4 S-выражения в JSON и обратно (Scheme). Списки превращаются в массивы JSON, ассоциативные списки в объекты, символы и строки в строки. Обратное преобразование читает JSON и строит S-выражение, проверяется, что после двух преобразований получается исходное выражение.
