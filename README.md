Индивидуальная работа по курсу «Новые языки программирования»: 20 программ на 20 разных языках программирования.

## Порядок работы

Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`,
например `1_task_1_rust`.
Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.
В папке каждой задачи есть свой README с постановкой и командами запуска.

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Параллельное умножение больших матриц | Rust | `1_task_1_rust` |
| 2 | Модель банка на программной транзакционной памяти | Clojure | `1_task_2_clojure` |
| 3 | Вычисление числа π методом Монте-Карло | D | `1_task_3_d` |
| 4 | Параллельное построение фрактала Мандельброта | Julia | `1_task_4_julia` |

1.1 Параллельное умножение больших матриц (Rust). Строки матрицы-результата делятся между потоками `std::thread`, исходные матрицы разделяются между потоками через `Arc`. Сравнивается время умножения на 1 и на N потоках, результат сверяется с однопоточным.

1.2 Модель банка на программной транзакционной памяти (Clojure). Счета хранятся в `ref`, несколько потоков одновременно переводят деньги между случайными счетами внутри `dosync`. В конце проверяется, что общая сумма денег в банке не изменилась, и печатается число выполненных и отклонённых переводов.

1.3 Вычисление числа π методом Монте-Карло (D). Случайные точки бросаются в единичный квадрат, доля попавших в четверть круга даёт оценку π. Точки делятся между потоками через `std.parallelism`. Печатается оценка, погрешность и время для разного числа потоков.

1.4 Параллельное построение фрактала Мандельброта (Julia). Строки изображения считаются параллельно через `Threads.@threads`, для каждой точки считается число итераций до ухода на бесконечность. Результат сохраняется в файл PGM, печатается время работы для разного числа потоков.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Задача о N ферзях (рекурсия) | Haskell | `2_task_1_haskell` |
| 2 | Калькулятор выражений методом рекурсивного спуска (рекурсия) | OCaml | `2_task_2_ocaml` |
| 3 | Задача о рюкзаке 0/1 с мемоизацией (рекурсия) | Common Lisp | `2_task_3_lisp` |
| 4 | Кодирование Хаффмана | Kotlin | `2_task_4_kotlin` |

2.1 Задача о N ферзях (Haskell). Рекурсивная функция ставит ферзя в очередную строку на каждую свободную позицию, не бьющуюся предыдущими ферзями, и переходит к следующей строке. Печатается число всех расстановок и первая найденная доска.

2.2 Калькулятор выражений методом рекурсивного спуска (OCaml). Выражение разбивается на лексемы, затем рекурсивные функции для выражения, слагаемого и множителя строят дерево с учётом приоритетов и скобок. Дерево вычисляется, ошибки в записи выражения сообщаются с указанием позиции.

2.3 Задача о рюкзаке 0/1 с мемоизацией (Common Lisp). Рекурсивная функция решает, брать очередной предмет или нет, уже посчитанные состояния запоминаются в хеш-таблице. После подсчёта восстанавливается сам набор выбранных предметов.

2.4 Кодирование Хаффмана (Kotlin). Считаются частоты символов текста, по ним строится дерево Хаффмана и таблица кодов. Текст сжимается в последовательность битов и восстанавливается обратно, печатается таблица кодов и степень сжатия.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Поиск по регулярному выражению в файлах (аналог grep) | Perl | `3_task_1_perl` |
| 2 | Построчное сравнение двух файлов (аналог diff) | Ruby | `3_task_2_ruby` |
| 3 | Консольная викторина с историей результатов | Lua | `3_task_3_lua` |
| 4 | Шифрование файлов шифром Виженера | Nim | `3_task_4_nim` |

3.1 Поиск по регулярному выражению в файлах (Perl). Программа ищет совпадения с регулярным выражением в нескольких файлах, печатает имя файла и номер строки, совпадения подсвечиваются цветом. Сводка по количеству совпадений в каждом файле сохраняется в файл.

3.2 Построчное сравнение двух файлов (Ruby). Для двух текстовых файлов строится наибольшая общая подпоследовательность строк, по ней определяются добавленные и удалённые строки. Результат печатается в консоль в виде, похожем на `diff`, и сохраняется в файл.

3.3 Консольная викторина с историей результатов (Lua). Вопросы и варианты ответов читаются из текстового файла, ответы пользователь вводит с клавиатуры. Неверный ввод переспрашивается. Результат, дата и затраченное время дописываются в файл истории, лучшие результаты можно посмотреть из меню.

3.4 Шифрование файлов шифром Виженера (Nim). Через консольное меню файл шифруется или расшифровывается побайтово по ключу, введённому пользователем. Есть режим проверки, который сравнивает расшифрованный файл с исходным.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | TCP-сервер голосования | Elixir | `4_task_1_elixir` |
| 2 | Файловый сервер на TCP | Erlang | `4_task_2_erlang` |
| 3 | Сетевые крестики-нолики | Scala | `4_task_3_scala` |
| 4 | UDP-сервер времени и измерение задержки | Zig | `4_task_4_zig` |

4.1 TCP-сервер голосования (Elixir). Клиенты подключаются по TCP и голосуют за один из вариантов. Состояние голосования хранит GenServer, каждый клиент обслуживается своим процессом. После каждого голоса текущие итоги рассылаются всем подключённым клиентам.

4.2 Файловый сервер на TCP (Erlang). Сервер на `gen_tcp` отдаёт список файлов из своего каталога и пересылает выбранный файл. Клиент запрашивает список, скачивает файл и проверяет его размер. Каждое подключение обслуживается отдельным процессом.

4.3 Сетевые крестики-нолики (Scala). Сервер принимает двух игроков, хранит игровое поле, проверяет допустимость ходов и определяет победителя или ничью. Клиент показывает поле в консоли и отправляет ходы.

4.4 UDP-сервер времени и измерение задержки (Zig). Сервер отвечает на UDP-запросы текущим временем. Клиент отправляет серию запросов, как `ping`, измеряет время ответа, считает потерянные пакеты и печатает минимальную, среднюю и максимальную задержку.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | JSON в YAML | F# | `5_task_1_fsharp` |
| 2 | INI в JSON | Swift | `5_task_2_swift` |
| 3 | CSV в HTML-таблицу | Groovy | `5_task_3_groovy` |
| 4 | S-выражения в JSON и обратно | Scheme | `5_task_4_scheme` |

5.1 JSON в YAML (F#). Собственный рекурсивный разборщик JSON строит дерево из объектов, массивов, строк, чисел и литералов true/false/null. Дерево печатается в YAML с отступами, строки берутся в кавычки, когда это нужно.

5.2 INI в JSON (Swift). Разбираются секции, пары ключ-значение и комментарии. Типы значений определяются автоматически: целые и дробные числа, булевы значения, строки. На выходе JSON-объект, где секции становятся вложенными объектами.

5.3 CSV в HTML-таблицу (Groovy). Свой разборщик CSV понимает кавычки, запятые и переводы строк внутри полей, удвоенные кавычки. Первая строка становится заголовком таблицы. На выходе готовая HTML-страница с экранированием спецсимволов и минимальными стилями.

5.4 S-выражения в JSON и обратно (Scheme). Списки превращаются в массивы JSON, ассоциативные списки в объекты, символы и строки в строки. Обратное преобразование читает JSON и строит S-выражение, проверяется, что после двух преобразований получается исходное выражение.
